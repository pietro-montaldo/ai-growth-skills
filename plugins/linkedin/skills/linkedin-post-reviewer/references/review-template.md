# Review template

Use this structure for every review.

```
## Overall assessment

[2 to 3 sentences: the post's biggest strength and its biggest opportunity. Specific and direct.]

## Scorecard

| Dimension | Score (1-5) | In one line |
| --- | --- | --- |
| Hook strength | | |
| Structure and scannability | | |
| Specificity and proof | | |
| Value clarity | | |
| Engagement architecture | | |
| Length and pacing | | |
| Authenticity | | |

## What's working

- [2 to 3 things the draft does well, and WHY they work. This is not flattery: it shows what to keep doing.]

## Suggested improvements

1. **[Dimension]:** what the issue is, why it matters, and a concrete rewrite.
   Before: [the line as written]
   After: [the suggested line]

[Order by impact: the change that would lift performance most comes first. Usually 2 to 4 items.]

## Revised version (optional)

[Only if asked, or if the changes are big enough that context is clearer. Keep the user's voice exactly. Change as little as possible for the biggest gain.]
```

## Edge cases

- **The draft is already strong:** say so. "This is strong, I'd only change X" is a valid review and earns trust.
- **The draft needs major rework:** be honest and constructive. Find the core idea worth saving and suggest a structure around it. Don't just list problems.
- **The topic is outside the user's usual niche:** the same voice and structure principles apply. Adjust what counts as proof for that topic.
- **Several drafts:** review each with the same framework, then say which to post first and why.
- **Images or carousels:** focus on the text. Flag it if the text and the visual don't match.
- **The hook is the main problem:** suggest the `linkedin-hook-generator` skill for alternatives.
